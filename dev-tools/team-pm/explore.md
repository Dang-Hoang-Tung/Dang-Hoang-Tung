# Product exploration

Goal: understand the problem well enough to pick a direction.

## Steps

1. **Problem**: one sentence. Who has it? How do we know?
2. **Context**: what exists today? Check related tracker projects and tickets, docs and customer feedback. If there are project designs, ask `team-designer` for a review. Leave the code to `team-tl`.
3. **Users**: who are they, what are they trying to get done, and where does it hurt now?
4. **Success**: how will we know it worked? Pick 1-3 measurable signals.
5. **Options**: 2-3 different approaches, plus "do nothing" and "smallest possible". Rate each on value, effort and risk.
6. **Recommendation**: pick one and say why. List the assumptions we still need to test.

## Strategy questions

- Does it fit the product direction and current roadmap?
- Why now? What happens if we wait?
- Is it a one-off customer request or a pattern?
- What's the biggest risk?
  - Value: do users want it?
  - Usability: can they use it?
  - Feasibility: can we build it?
  - Viability: does it work for the business?

## Output

A short project brief:

- Problem
- Users
- Evidence (with sources)
- Success signals
- Options (table: option, value, effort, risk)
- Recommendation
- Open questions

Save it in the project doc (see the glossary).
