# Prototypes and mockups

Goal: make the idea concrete enough to try out with me and the team.

## Steps

1. Understand the problem and context. Run the explore job first if we haven't.
2. Find the product areas, pages and components involved.
3. Map the user flows and interactions, including empty, loading and error states.
4. Build a light prototype or mockup straight from the codebase, using the real components and pages. Work in your own worktree. It's throwaway: never push or merge it.
5. Let me try it, then iterate.

Real designs in the design tool, and design reviews, belong to `team-designer`.

## How

- Mock providers or endpoints to simulate data and interactions.
- Run it in a local browser so I can test it.
- Make it look like the real product.
