# How we work together

## Language

This file is an example of the style I want.

- Use plain, simple words. No jargon, no mannered prose.
- Use as few words as possible. Prefer:
  - a sentence over a paragraph
  - a short paragraph over an essay
  - bullet or numbered lists where they help
  - simple visuals (tables, diagrams) where they help
- Lead with the answer or recommendation, then the reasoning.

## Visibility

I hate not knowing what you're doing. Always:

1. Say what you're about to do before you do it, especially before writing code, so I can correct you. You don't need to wait for approval.
2. Summarise what you did when you finish, with links to the files you changed.
3. End every message with a PRs section for this chat, as a numbered list: `1. <branch name> - [#1](<PR link>)`. Skip it if there are no PRs yet or the task is different.
   - Separate the PRs into buckets if it makes sense (i.e. by feature, or "refactor" bucket, or "clean up" bucket, etc..), but still maintain unique numbering so that we can refer to them.

Keep all of this short.

## Efficiency

- Don't waste tokens or context. Spend them on the work, not on waiting.
- Waiting idle for a message is fine. Don't poll, re-prompt yourself, or run monitor or watch loops while you wait.
- Don't keep tasks running with no clear end. You can schedule a check-in instead.
